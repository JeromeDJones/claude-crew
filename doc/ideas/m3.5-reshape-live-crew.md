# M3.5 — Reshape a Live Crew

**Status:** DESIGN LOCKED (2026-06-30, Kael + Jerome) — ready for repo-react planner
**Arc:** Workflow Shape Composition (M0 → M1.5 → M2 → M3 → **M3.5**)
**Predecessor:** M3 Adaptation Algebra (pure-data verbs) — `doc/features/FEATURE-m3-adaptation-algebra.md`

---

## Purpose

M3 made shape adaptation *computable* — five pure verb commands (`AddNode`/`Swap`/`Augment`/`SetGate`/`Drop`), each `Shape → (Shape, AdaptationDiff)`, exposed via `adapt_shape`. But M3 is **pre-instantiation only**: it produces a new proposed shape that goes through the human gate and then `instantiate_shape` spawns a **fresh** crew.

M3.5 applies those same verbs to an **already-running (instantiated) crew** — mutate the live topology in place:
- `Swap`/`Drop` kill (and, for swap, respawn) live teammates.
- `AddNode`/`Augment` add teammates/edges into the running topology **without disturbing running teammates**.
- `SetGate` rewires routing modes mid-flight.

claude-crew owns the *mechanism*; repo-react (policy) owns *which* reshape to apply.

## Seam facts (verified 2026-06-30 — do not re-derive)

Routing and gate internals the planner can rely on:

1. **Routing reads live broker state at delivery time — not a frozen snapshot.**
   - `_send_routed → _resolve_routing_mode → _active_topology_for(sender,recipient)` scans `reversed(broker._topologies)` (a **mutable list**, latest-appended wins).
   - `_edge_mode` checks `broker._edge_overrides[(from_slot,to_slot)]` **first**, then the topology's `edges` tuple.
   - **Consequence:** rewiring is a *data update*, not a crew rebuild. Membership change → append a new frozen `Topology`; mode change → write `_edge_overrides`.

2. **`authorize_send` (broker.py:1560) is the security boundary — checked at delivery time.**
   - `send_scoped(sender, recipient, payload)` → `_resolve_scoped_recipient` → `authorize_send` → raises `UnauthorizedEdgeError` when no active topology contains both, or no forward edge exists.
   - The `send_to` **tool's presence is NOT the gate.** A teammate holding the tool but lacking an authorized edge gets a clean `UnauthorizedEdgeError`.

3. **`send_to` MCP tool is free-form.** Schema `{"recipient": str, "payload": dict}` — `recipient` is any slot name or teammate id (`sdk_teammate.py:1375-1407`). No enumerated allowlist. So telling a running teammate about a new neighbor via a **message** is sufficient for it to use the edge — provided the tool is wired in its subprocess.

4. **`send_to` wiring is currently spawn-time + conditional.** `_run()` gates on `_has_out_edges` (`sdk_teammate.py:1543-1560`); a teammate spawned with zero out-edges never gets the tool wired, and it **cannot** be injected into a live subprocess. → see Deliverable 0.

5. **Neighbor prompt section is spawn-time cosmetic.** `build_teammate_prompt(..., neighbors=)` bakes a "Crew neighbors" section at `__init__` (`teammate_prompt.py:91-186`). Stale after a live add; the runtime informing-message supersedes it.

6. **The M1.5 human gate is fully reusable, untouched.** `register_proposal` / `await_proposal` / `resolve_proposal` / (state machine `pending→approved|declined|timed_out→instantiated`). `adaptation_diff:str` channel already carries reshape-diff context to the dashboard. Only the *consumer* (`instantiate_shape`, hardwired to spawn fresh) needs a sibling that applies live mutations.

7. **`Topology` is frozen; `broker._topologies` is a mutable list.** `record_topology(topo)` just appends; `_active_topology_for` uses `reversed(...)` so the newest matching topology wins. `BrokerSnapshot.topologies` is a snapshot tuple — dashboard/status consumers never hold a live reference, so appending during operation is safe.

8. **Existing kill machinery is sufficient.** `kill_teammate(graceful, flush_timeout)` → optional `begin_graceful_termination` → `_tombstone_teammate` (idempotent; marks `alive=False`, pops from `_teammates`/`_inboxes`, bounces in-flight + queued envelopes, fire-and-forget subprocess shutdown). No new lifecycle state needed.

## Locked design decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | **Live reshape is human-gated** — reuses the M1.5 gate verbatim (propose reshape → human approves/declines → apply). | Coordinator-in-the-loop is the moat. Killing a running teammate is exactly the high-consequence act the gate exists for. `adaptation_diff` already carries the diff. |
| D2 | **Distinct `reshape_crew` MCP tool** — shares the five verb command objects from `shapes.py`; applies **live** mutations. `adapt_shape` stays pure-data. | Live process side-effects (kill/respawn/authorize) have different semantics than a pure-data proposal; overloading one tool invites "did this kill a process?" confusion. Verb algebra is shared; only the *application* differs. |
| D3 | **`send_to` wired unconditionally at spawn** (drop the `_has_out_edges` gate). | Makes live edge-addition respawn-free. Safety unchanged — `authorize_send` is the real boundary (seam 2). Cost is a bounded contract flip ("plain SdkTeammate has no send_to" → now always present) + its tests. |
| D4 | **Additions never respawn — authorize + inform.** `AddNode`/`Augment` that add an out-edge to a running teammate → append `Topology` (authorize) + send that teammate an informing message ("new neighbor `X`, reachable via `send_to`"). | Preserves accumulated turn context (Jerome's explicit priority). Enabled by D3 (tool always present) + seam 3 (free-form recipient) + seam 5 (message supersedes stale prompt). |
| D5 | **Swap/Drop kill by nature.** Swap: **spawn replacement (new id, same slot) + record new `Topology` → then** graceful-drain-and-kill old (this ordering leaves no dead-slot window). Drop: new `Topology` minus node/edges + graceful-kill + clean stale `_edge_overrides` + inform affected neighbors. | Membership *removal/replacement* has no context worth preserving on the removed teammate. Ordering closes the kill→record race (seam 8 race note). |
| D6 | **Stale `_edge_overrides` cleanup on edge removal.** Drop/Swap that remove edges must delete their `(from_slot,to_slot)` override entries. | Overrides are keyed by slot strings and survive topology replacement — a stale override would shadow the new topology's declared mode. |

## Per-verb live semantics

| Verb | Live action | Respawn? |
|------|-------------|----------|
| **SetGate** | Write `_edge_overrides[(from,to)] = mode`. Instant, live. | No |
| **AddNode** | Spawn the new teammate (correct neighbors at *its own* launch) + append new `Topology`. If the wiring edge's **source** is an already-running node → inform it via message. | No (source stays up) |
| **Augment** | Authorize the new edge (append `Topology`) + inform the source running node via message. | No |
| **Drop** | New `Topology` minus node + its edges; graceful-kill the teammate; clean stale `_edge_overrides`; inform affected neighbors their edge is gone. | Kills dropped node |
| **Swap** | Spawn replacement (new id, same slot, correct neighbors) → record new `Topology` (slot→new id) → graceful-drain-and-kill old. | Replaces target |

## Race / correctness notes

- **Kill→record window (Swap):** ordering is **spawn-new + record-topology → then tombstone-old**, so slot-name sends resolve to the live replacement throughout; no window where the slot maps to a dead id.
- **`_edge_overrides` persistence:** survives topology replacement → D6 cleanup on removal.
- **Topology append atomicity:** single asyncio loop + GIL make `reversed(_topologies)` during `list.append` safe for the MVP. A message that resolved routing just before an append uses the old topology; just after, the new — both deterministic. No lock needed now (note for any future multi-threaded broker refactor).

## Deliverables

- **D0 — Unconditional `send_to` wiring.** Remove the `_has_out_edges` conditional in `sdk_teammate.py:_run`; wire the in-process `send_to` MCP server + allowed-tools entry for every SdkTeammate. Flip the documented contract; update the tests that assert plain-teammate has no `send_to`. (Foundational — everything else depends on it.)
- **D1 — `reshape_crew` MCP tool** in `server.py`: verb discriminator (reuse `shapes.py` verb objects) → resolve base *live topology* → gate (register_proposal / await) → on approve, apply live mutations per the verb table → record new `Topology` / write overrides → send informing messages → return structured result. Reuse the M1.5 gate; keep `broker.py` changes minimal and additive.
- **D2 — Broker live-reshape support** (broker.py, additive): whatever minimal helpers the tool needs to (a) resolve the active topology for a running crew, (b) append the reshaped topology, (c) clean stale overrides, (d) send an informing message to a running teammate. Prefer reusing `record_topology` / `_edge_overrides` / existing `send` / `kill_teammate`.
- **D3 — Live tests (regression guard, run before merge):**
  - **Headline (no-respawn add):** instantiate a real crew; live-reshape to add `reviewer` + edge `impl→reviewer`; assert the **same still-alive** implementor (same teammate_id, not respawned) receives the informing message, calls `send_to("reviewer",…)`, and the reviewer receives it. Must assert a **real teammate turn/response**, not stub-satisfiable structure.
  - **Swap:** live-reshape swaps a slot's role; assert old teammate dead, new one in the slot, and a slot-name `send_to` resolves to the **new** teammate.
- **D4 — Stub tests:** topology append semantics, `_edge_overrides` write + stale-cleanup, gate state-machine integration, per-verb decision logic, inform-vs-nothing branch, D0 contract flip.

## Out of scope

- Live *tool-set* mutation of a running subprocess beyond what D0 pre-wires (SDK bakes allowed-tools at launch) — hence D3/D0 rather than live tool injection.
- Autonomous (ungated) reshape — that's M5 (memory-informed adaptation). M3.5 stays gated.
- RepoReactor-as-shape (M4).
