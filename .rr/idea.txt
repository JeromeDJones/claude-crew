M2 — Edge routing policy + scoped teammate send_to (the comms substrate)

This is milestone M2 of the Workflow Shape Composition arc. M0 (shape-as-data +
shape-gate) and M1.5 (async/resurfaceable shape-gate) already shipped. M2 makes the
topology recorded in M0 actually GOVERN message flow instead of being decorative
metadata. Scope this as ONE slice covering all five components below.

OUTCOME
The Topology recorded at instantiate_shape time (broker.py: Topology.edges + per-edge
mode) starts enforcing routing. Per-edge mode is honored by the broker; teammates can
message each other but ONLY along their declared out-edges, and ONLY within a
circuit-breaker budget that force-inserts the lead before anything runs away.

IN SCOPE (all five — single slice):

1. Per-edge routing enforcement in the broker.
   Three modes:
   - gated  = lead inbox first (today's behavior; the DEFAULT, resolved 2026-06-11)
   - tee    = delivered direct to recipient AND cc'd to the lead
   - direct = delivered direct to recipient, logged to the broker, NOT in lead inbox
   Today broker send routes purely by `recipient`. Add the policy gate keyed on the
   recorded Topology.edges for the active topology. Messages with no governing edge
   fall back to today's behavior (lead-routed / gated).

2. Scoped teammate send_to.
   Teammates gain a send capability scoped to their declared out-edges ONLY — the
   topology IS the authorization layer. This is the core structural change. Today
   `recipient=env.sender` is hardcoded in sdk_teammate.py (~line 1706) and teammates
   hold no send tools. A send to a non-declared recipient must be rejected (loudly,
   not silently dropped).

3. Neighbor adjacency injection at spawn.
   Each teammate is told who it is wired to and how, e.g. "you can consult
   plan-reviewer (direct); verdicts arrive from slice-reviewer (gated)". Without this
   the edges exist but never get exercised by the teammates.

4. Circuit breaker on direct/tee edges — NON-NEGOTIABLE autonomous-chatter guard.
   - max exchanges per edge before the lead is force-inserted
   - per-edge token/turn budget
   - deadlock detection (A waits on B waits on A)
   direct edges DO NOT SHIP without this guard in place.

5. Dashboard observability.
   - edges animate on the dashboard when messages flow across them
   - click an edge -> see that edge's message log
   - operator can PROMOTE an edge to `gated` mid-run to step back onto it
   Honor the multi-instance leader/follower rule (see CLAUDE.md): any NEW per-instance
   endpoint MUST carry crew_id and proxy leader->follower, and needs a multi-instance
   test, not just a single-instance one.

NON-NEGOTIABLES (the moat invariants — do not violate):
- Observable by construction: every cross-teammate message still routes through the
  broker — sequenced, logged, surfaced to Mission Control. NO off-broker peer channels.
- Coordinator stays on judgment edges: per-edge policy may remove the lead from RELAY,
  never from GATE.
- Default edge mode is `gated`. Loosening an edge to tee/direct is always an explicit,
  deliberate act — never the default, never by omission.
- Bonded to the Claude Agent SDK / existing SdkTeammate+broker substrate. Do NOT adopt
  an external orchestration runtime.

EXPLICITLY OUT OF SCOPE (later milestones — do not build these here):
- The adaptation algebra verbs add_node / swap / augment / set_gate / drop (that is M3).
- The blessed shape library + lead right-sizing classifier (that is M1).
- Re-authoring RepoReactor as a native heavy-feature shape (that is M4).
- Any autonomous / memory-driven adaptation or widening of lead latitude (that is M5).

VALIDATION EXPECTATIONS (two layers, happy + sad, per the repo's standards):
- Broker per-mode routing unit tests: gated routes to lead inbox; tee delivers direct
  AND cc's lead; direct delivers direct + logs but stays out of lead inbox.
- Integration: a `direct` edge ping-pong between two teammates stays OFF the lead's
  inbox but DOES appear in the broker message log + the dashboard state.
- Sad: exceeding the circuit-breaker budget force-inserts the lead; a scoped send_to to
  a non-declared recipient is rejected.
- Dashboard: a multi-instance test (leader aggregating a follower's edges), not just a
  single-instance test — per the CLAUDE.md leader/follower trap.
- The FULL test suite (uv run pytest) must stay green — M2 changes widely-consumed
  broker/teammate behavior, so validation must run the whole suite, not a -k subset.
